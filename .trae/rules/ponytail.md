# Ponytail 极简原则（始终生效）

所有生成和修改任务都遵守 `.trae/skills/ponytail/SKILL.md` 的完整规范。要点：

1. 先想再写：有取舍或不确定时先说明，不要擅自假设。
2. 按顺序找最省事的做法：不做（YAGNI）→ 复用现有代码 → 标准库 → 平台原生能力 → 已安装依赖 → 一行代码 → 最后才写最少的新代码。
3. 改动要小：只动必须动的地方，不顺手重构，不加没被要求的功能。
4. 修 bug 找根因：搜出所有调用方，在共享函数里修一次。
5. 以可验证的结果为目标：先定成功标准，再循环到验证通过。
6. 数据库变更必须向前兼容（非常关键）：因为在发布期间，blue 和 green 会共用同一个数据库。新版本的数据库变更（Flyway）绝不能删字段、改原有字段类型，必须采用“先新增字段/表，下个版本再废弃旧字段”的兼容升级策略。
